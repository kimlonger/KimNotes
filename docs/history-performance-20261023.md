# 便签列表性能及同步状态（2026-10-23）

便签列表原先在窗口 Load 中逐篇调用 RichTextBox.LoadFile，并且每次激活窗口或便签更新都销毁、重建所有卡片。图片的 RTF 编码会被 RichEdit 完整解码；这会阻止窗口首次绘制，也会使切回列表时再次卡顿。

本次调整：

- 文件快照、索引缓存加载、RTF 文本解析和索引落盘改到独立 STA 后台线程。列表先显示窗口，未索引的可见便签短暂显示“正在加载…”。首个结果及时更新，后续结果分批更新。
- 在交给 RichEdit 前剔除图片及 OLE 内容，只生成文字预览和完整搜索文本。保留 RTF 原有编码；处理转义括号和 `\\bin` 原始二进制长度。原始便签及图片不被改写。
- 缓存复用修改时间及文件长度一致的文本。原子保存成功后可调用 `NoteIndex.UpdateFromText(path, plainText)`，仅更新内存，不在每次保存时序列化、重写全部索引。
- 只为可见区域创建原生 RichTextBox 卡片。已创建且未删除的卡片在激活、刷新和修改后继续复用，保留滚动位置。主题元数据也只在需要卡片时读取。
- 登录时在日期旁显示“已同步 / 待同步 / 同步中 / 同步失败 / 需重新登录”，失败原因放在悬停提示中；状态事件仅更新可见卡片的标签，不重新索引或重建列表。退出/切换账号立即清除旧账号卡片，过期的后台回调不能重新显示它们。
- 维持预览 9pt、日期/状态 8pt，并在 DPI 变化后重新计算高度而不重建卡片。窗口关闭会取消解析并移除存储/同步事件订阅。

## 专项验证

`tests/HistoryRegression.cs` 使用独立的 `KIMNOTES_DATA_DIR`、合成账号和本地图文便签；不登录真实账号、不访问云服务。它编译为现有友元程序集名 `CloudRegression.exe`，单独运行，与 `tests/CloudRegression.cs` 的运行器互不混编。

覆盖响应性（主动锁住索引线程时仍能处理 UI 回调，而非依赖机器性能的毫秒断言）、图片 RTF、完整搜索、缓存复用、卡片引用复用、滚动位置、保存内存更新、主题、状态及失败原因、账号隔离、关闭时的后台工作，以及实际 120/144 DPI 屏幕间反复移动。

最新专项结果：**26 项通过**。截图及合成数据保留在测试输出的临时目录中；已在主目录集成实际同步状态后复测通过，Release 构建无警告。

现有 UI 测试需适配异步加载：`history.Show()` 后用 `Application.DoEvents()` 配合有限超时，等待私有字段 `previewLoading == false` 且 `refreshTimer.Enabled == false`，再检查全文搜索、滚动和排版；不要仅调用一次 `DoEvents()`，也不要加入固定延迟。原先 `allCards` 仍表示所有可见账号的便签，`panel1.Controls` 则只包含已经进入过可见区、按需创建的原生卡片。
