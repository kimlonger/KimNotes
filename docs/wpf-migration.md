# 小羊便签 Windows 版 WPF 迁移方案

以 WinForms 1.4.23 封存提交 `29983d9` 为功能与样式基线，在 `work/wpf-net48-migration` 上迁移到 **WPF + .NET Framework 4.8**。正式验收覆盖 Windows 10 22H2 和 Windows 11，按现有界面核对标题栏、Logo、配色、字号、默认大小、按钮和操作流程。优先改进圆角、多屏拖动和缩放、输入法、列表滚动与设置应用。

各阶段在迁移分支内依次验证，所有功能接通后交付同一个测试包。各阶段验收项保留为全量测试清单。正式发版在全量验收后另行安排。

## 目标架构

| 层 | 职责与边界 |
| --- | --- |
| 领域 | 便签内容与状态、待办重复和完成规则、提醒去重、传输状态等业务概念。不持有窗体、网络连接、磁盘路径、计时器或系统句柄。 |
| 应用用例 | 串联新建、保存、搜索、恢复、同步、文件互传、设置应用等用例，管理取消、协调和失败结果。通过面向具体用例的接口请求存储、身份或系统能力。 |
| 基础设施 | 实现本地文件、备份、索引、DPAPI、HTTP、同步协议和传输协议等。保留现有格式、类型转换与错误处理规则。 |
| WPF 表示层 | XAML、主题资源、窗口、视图模型和编辑器适配。视图负责布局与交互，视图模型负责页面状态和命令，代码后置承接需要 WPF 控件的焦点与窗口事件。 |
| Windows 平台适配 | 封装全局快捷键、托盘、自启、窗口定位、DPI、截图和系统对话框，向应用与窗口组件提供明确接口。 |
| 程序入口 | 组装依赖，管理进程、单实例和模块生命周期。入口只负责装配与退出协调。 |

依赖方向为 **WPF → 应用用例 → 领域**。基础设施和 Windows 适配实现用例所需的接口，由入口注入。优先按领域与功能目录保持边界，再根据构建和复用需求划分程序集。一个类负责一类紧密相关的行为，跨功能的流程由应用用例协调。同步的会话、调度、文档转换和冲突处理独立，文件互传的连接、会话、文件收发和界面独立，配置的草稿、落盘和运行时应用独立。

保留已经验证的原子写盘、HTTP 客户端、同步计划、文件互传协议和加密实现。逐步替换同步中的 WinForms 定时器和全局窗体访问，富文本、图片和输入法通过编辑器适配承接。分离待办规则、保存、提醒调度和错误提示。 [本地存储](../utils/Storage.cs) · [账号 API](../utils/CloudApi.cs) · [同步编排](../utils/CloudSync.cs) · [云端文档](../utils/CloudDocuments.cs) · [待办](../utils/TodoStore.cs) · [互传协议](../main/FileTransferProtocol.cs)

## 界面与配置

- 应用窗口共用标题栏、边框、主题和矢量图标资源。在 WPF 透明窗体内绘制圆角，以逐像素透明平滑外沿。窗口内容和标题栏统一裁切，顺滑滚动和列表虚拟化以保持布局稳定为前提。
- 便签预览采用 301 × 401 DIP 的基准窗口，标题栏与底部工具栏均为 31 DIP 高。闲置隐藏操作栏时保留正文的起点和可视高度。Windows 10 与 11 均覆盖 100%、125%、150%、200% 及混合缩放，外接屏设在主屏左侧或上方，覆盖负坐标。测试深浅桌面背景和跨屏松手，从首次显示到贴边展开观察黑角、阴影和残影。
- 设置先维护独立草稿，再由一个应用用例验证、应用并原子保存。保存后发布一次设置变更，打开窗口、提醒、截图、热键和传输组件使用相同配置。
- 开机启动同步修改注册表。主题与任务栏选项通知打开窗口。提醒在下次触发时读取新值。截图保存路径在下次截图时读取。后台接收开关立即更新监听，已接收的传输保持原有完成或取消流程。热键验证整组重复与系统占用，换绑失败后恢复旧绑定。
- 无痕和笔记目录更换涉及已有窗口、待办缓存和进行中的同步。先暂停受影响工作并确认保存成功，校验并复制便签与备份，切换后重新加载活动窗口、索引和会话。目标目录有同名不同内容的文件时保留双方文件并显示冲突。仅整次应用成功才确认新配置。失败恢复旧配置和运行状态，保留待保存内容并显示可处理的错误。无痕数据使用单独内存状态，退出无痕时重新载入普通数据。确有运行约束时说明原因，保留用户确认的重启入口。
- 维持 `config.txt` 的读取兼容、未知键保留、旧默认快捷键的迁移及自定义快捷键。配置写盘采用同目录临时文件、原子替换和备份，运行态与磁盘变更作为一次配置应用提交。 [配置读写](../utils/InitConfig.cs) · [现有保存逻辑](../settings/ConfigForm.cs) · [快捷键注册](../utils/HotKeyHandlerForm.cs)

## 数据与清理原则

- 保留便签 `.rtf`、`.rtf.meta.json`、备份、打开会话、索引、截图历史、待办和提醒记录。保持 DPAPI 会话、便签所有者、同步游标和账号隔离。测试兼顾 WinForms 到 WPF 的升级，以及 WPF 写回后由 WinForms 读回。
- 样本覆盖中文、列表、粗体、删线、不同尺寸的内嵌图片、云端附件、已保存后清空的便签、备份恢复、写失败、冲突副本、删除与找回、历史回滚、首次同步中断和重复请求。应用端继续使用现有账号与 API、文件传输及线上会话协议。
- 每阶段清理已验证无调用的设计器隐藏控件、纯重复绘制、失去用途的验证和未编译草稿。删除前检查静态引用、项目编译列表、系统回调和测试覆盖。配置兼容键、旧取件码和旧版本协议在兼容验收期间继续保留。确认配置热更新的回归通过后，再退役对应的旧重启路径。 [编译清单](../KimNotes.csproj) · [数据目录与回归](development.md)

## 阶段交付与验收

| 阶段 | 交付 | 阶段验收门槛 |
| --- | --- | --- |
| **1　验证 WPF 窗体与编辑器** | 独立预览项目 `desktop/KimNotes.Windows/KimNotes.Windows.csproj`，输出 `KimNotes.WpfPreview.exe`。主便签延续原有比例、标题栏和颜色，试验透明矢量圆角、拖动和调整尺寸、当前固定像素 DPI 行为。提供粗体、删线、列表、新建、置顶，`Ctrl+O` 打开指定 RTF 样本，`Ctrl+S` 保存独立测试副本。 | 用 Win10 与 Win11 对照 WinForms 的同一默认窗口，检查圆角、文字和工具栏。用混合 DPI 双屏拖动、释放和调整尺寸。使用微软拼音输入、选词和撤销，通过样本验证 RTF 保存到新文件，然后重新打开。记录字体、图片和布局差异。预览以显式选择的样本为数据边界，贴边从阶段 2 接入。 |

| **5　迁移账号、同步与历史版本** | 接入账号、头像和同步状态，恢复本地会话兼容，接入历史列表/预览/恢复，便签和待办同步及来源设备。 | 两个版本间离线改动后恢复同步，验证数据、格式和图片，验证并发冲突、删除恢复、同步中断/续传、账号隔离、历史恢复和返回列表。 |
| **6　迁移桌面工具和文件互传** | 复用通信协议与加密，迁移文件和目录发送、取件码接收、保存路径选择、后台运行与提示。 | 测新旧客户端互发、同网优先、跨网回退、后台确认与通知。覆盖空目录、重名、拒绝/取消、掉线、文件一致性、临时文件清理和登录退出后的权限变化。 |

自动化测试通过 `KIMNOTES_DATA_DIR` 使用独立目录和模拟数据。WPF Dev 默认沿用旧版的 `%AppData%\KimNotes`、配置中的便签和图片目录、待办和登录会话。此前使用的 `%LocalAppData%\KimNotes.WpfPreview` 仍保留。切换版本前先从托盘退出正在运行的一版。多屏、输入法、长时间待机及真实网络互传以真机验收为准。

## 构建与复查

在装有 .NET Framework 4.8 目标包的 Visual Studio 开发者命令行里，从仓库根目录恢复依赖、构建并复查。

```powershell
nuget restore KimNotes.sln
msbuild desktop\KimNotes.Windows\KimNotes.Windows.csproj /p:Configuration=Release
powershell.exe -NoProfile -Sta -File tests\wpf-preview.ps1 -Executable desktop\KimNotes.Windows\bin\Release\KimNotes.WpfPreview.exe
powershell.exe -NoProfile -Sta -File tests\wpf-migration.ps1 -Executable desktop\KimNotes.Windows\bin\Release\KimNotes.WpfPreview.exe
```

离屏测试覆盖便签界面、四角透明过渡、基础格式操作、RTF 往返和隔离目录内的旧数据读写。测试包解压后运行 `KimNotes.WpfPreview.exe`。联网测试继续使用本地构建配置注入，通过 `KimNotesEndpointsFile` 和 `KimNotesBaiduCredentialsFile` 分别指定服务地址与百度配置。
