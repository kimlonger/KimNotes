# 网页与桌面登录会话实施说明 · 2026-10-23

方案已实现，并完成隔离数据库、官网及桌面回归验证。最终部署结果见 session-release-2026-10-23.md。API 始终使用 HTTPS 域名；网页和桌面各自执行下列会话期限，桌面密码不落盘。

## 已实现参数

| 项目 | 官网网页 | Windows 桌面 |
| --- | --- | --- |
| 登录入口 | 官网邮箱、密码及现有人机验证 | 本机邮箱、密码，无人机验证；注册打开系统浏览器 |
| 访问凭证 | 服务端随机会话 ID，通过 Cookie 发送 | 15 分钟随机 Access Token，仅用于 API |
| 无操作期限 | 30 分钟 | 设备 180 天未成功续期 |
| 最长会话 | 首次登录起 8 小时，到期重新登录 | 正常使用时自动续期，可长期免登录 |
| 长期凭证 | 默认不签发、不显示“记住我” | 180 天滚动 Refresh Token，每次续期更换 |
| 本地保存 | Secure / HttpOnly / SameSite=Lax 的 __Host Cookie；不将 Token 放 localStorage | 访问 Token 放内存，Refresh Token 与待重试状态由当前 Windows 用户 DPAPI 加密保存；不保存密码 |

网页的空闲与绝对期限由服务端同时检查；客户端提示不代替服务器验证。浏览器后台同步和页面计时不延长空闲期限。

网页关闭后 Cookie 可以采用浏览器会话 Cookie，但不能依靠“关闭浏览器”判定安全退出，因为浏览器可能恢复会话；最终以服务器的 30 分钟/8 小时校验为准。同站从官网切到便签、普通页面刷新不会直接退出。

## 网页流程

1. 验证通过后建立 web session，记录 created_at、last_activity_at、absolute_expires_at、revoked_at 与账号安全版本。
2. 页面在用户近期有鼠标、键盘、触摸等操作时节流上报活跃，服务端更新 last_activity_at。便签自动轮询、隐藏标签页和刷新 Cookie 不更新用户活跃时间，避免网页开着就永不失效。
3. 30 分钟无操作或登录满 8 小时后，服务端拒绝会话。客户端先在当前标签页 sessionStorage 保留按账号隔离的未保存草稿，再要求登录；相同账号登录后恢复，由用户确认保存。过期 Cookie 无法继续访问，主动退出时清 Cookie。
4. 会话 ID 每 30 分钟轮换，轮换不重置 8 小时上限。旧 ID 有 1 分钟并发宽限，支持 Set-Cookie 丢包恢复。请求携带 X-Kim-Expected-User，账号切换后返回 409 account_changed，保护原账号草稿并锁定旧页面。
5. 写操作继续检查 Origin、CSRF 和现有网关验证。Cookie 保持 host-only，不跨所有子域共享；关闭浏览器不替代服务端撤销。

## 桌面流程

1. 首次登录返回 Access Token、Refresh Token、expiresIn、sessionId。账号验证完成就显示“已登录”；便签与图片在后台同步并独立展示状态。
2. 启动时读取 DPAPI 保护的 Refresh Token，静默换取 Access Token，不重复发送密码。访问凭证临近到期或首次收到明确的 access_expired 时，只续期一次并重试原请求。
3. 每次续期在事务中消耗旧 Refresh Token、签发新的一对凭证，并把设备有效期推到本次成功续期后的 180 天。经常使用时不会因为 15 分钟或原有 30 天限制而弹登录；180 天完全没有成功续期，再次使用需要验证账号。
4. 同一客户端只允许一个续期请求进行，其他同步请求等待该结果。新凭证先原子落盘，再替换内存状态和重放请求。
5. 网络错误、超时、429、5xx 进入离线/退避重试，保留账号身份和本地内容，不判成“密码错误”。服务器明确返回 refresh_expired、refresh_revoked、account_disabled 等不可恢复状态时，停止联网同步、移除失效凭证并提示重新登录，保留原账号本地副本和所有权。
6. 修改/重置密码、主动退出、远程撤销设备、确认凭证重放，都可以终止长期登录。桌面不持续检测密码，也不会保存密码反复尝试登录。

Refresh Token 使用后轮换，并检测已消费凭证重用；这是面向公开客户端的标准安全措施。设备名称、设备 ID 和 IP 仅用于展示与审计，不能当成持有凭证的证明，不将换网络或换 IP 当成退出条件。[RFC 9700 §4.14](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)

### 续期丢包与并发

桌面持久化 refresh_request_id 后才发请求。服务端将结果绑定到原凭证代次与此请求 ID；5 分钟内以相同 ID 重试时，只返回同一次换领结果，不再次换代。包含新凭证的幂等响应仅短时加密缓存，主凭证表只保存哈希。相同旧凭证被其他请求 ID 再次使用时，撤销该设备的凭证家族并记录原因。客户端后台任务、主窗口与多个同步任务共享同一个续期锁。

响应缓存过期且客户端确实没有保存到新凭证时，需要重新验证，不能无限接受旧凭证。后续可增加 Windows CNG 设备私钥证明；仅凭 device_id 不允许恢复已失效凭证。

### 退出与密码变更

- “退出当前设备”撤销当前 session 及其全部访问/刷新凭证，不影响其他设备。
- “退出所有设备”、修改/重置密码递增用户 auth_version，撤销所有应用中的既有会话；用户重新登录后获得新会话。
- 离线退出立即移除本机凭证。服务器尚未收到撤销时，不声称已在服务器退出；设备管理可执行远程撤销。
- 每次访问检查 session 撤销与账号版本，采用现有数据库查询路径即可即时生效，不要求引入 Redis 或单独 JWT 服务。

## 表结构与应用隔离

保留 users / applications / user_apps：用户身份全局唯一，应用内容始终通过 (app_id, user_id) 隔离。一个账号可登录多个应用，不代表一个应用的 Token 可以访问其他应用。

- users 增加 auth_version、password_changed_at，作为全应用撤销依据。
- sessions 增加 UUID id、device_id、last_activity_at、idle_expires_at、absolute_expires_at（桌面可为空）、revoked_at、auth_version。保留 user_id、app_id、client_kind；网页会话 Cookie 哈希独立于桌面 API 凭证。
- access_tokens：token_hash、session_id、expires_at、created_at；限 desktop 类型及指定 app_id。
- refresh_tokens：token_hash、session_id、generation、expires_at、consumed_at、replaced_by。session_id 即设备凭证家族；request_id、加密 result 与 result_expires_at 一并存放，用于 5 分钟恢复，不另建重复的 refresh_results 表。
- web_cookie_aliases / desktop_upgrades：短时 Cookie 并发与旧桌面凭证升级恢复。加密恢复结果每 5 分钟清理，已消费哈希保留用于重放检测。
- auth_events：session_id、user_id、app_id、事件类型和时间；记录登录、续期、升级、重放、退出、撤销、密码变更，保留 90 天，不记录密码、原始 Token 或完整认证请求。

所有业务接口从服务器验证过的身份取得 app_id / user_id，忽略请求体自行声明的用户身份。新增应用不复制 users 表；未来需要真正的浏览器跨站单点登录时，再在统一账号域引入标准授权码与 PKCE，不共享宽域 Cookie。

## 接口和实施次序

- 保留 POST /api/v1/apps/{app}/auth/login 和 /auth/desktop/login 的邮箱密码登录方式；网页登录仍有人机验证，桌面没有。
- 增加 /auth/desktop/refresh、/auth/desktop/upgrade、GET /auth/sessions、DELETE /auth/sessions/{id}、POST /auth/logout-all；刷新、升级只接受相应类型凭证。
- 先在隔离测试环境迁移表、验证撤销和轮换，再发支持刷新机制的桌面版。旧版有效 desktop Bearer 在有限迁移窗口内可一次换领，旧凭证随即作废；过期/已撤销凭证不允许升级。
- 官网原有 30 天会话按新上限失效，可能需要重新登录一次；更新提示文案和草稿保护。旧桌面 API 的过渡不放宽新的网页会话期限。
- 必测：绝对/空闲到期、后台轮询不能续命、跨标签页、客户端重启、离线、续期丢包与并发、旧刷新凭证重放、改密码竞争、当前/全部设备撤销、跨应用和跨账号隔离、凭证类型混用。

## 官网便签展示（已实现）

改为“便签卡片总览 + 点击后侧边阅读”，让内容成为页面主体。沿用官网现有白、浅灰、蓝色和桌面便签的主题色，不在账号区放产品图。

- 左侧约 176 px 的轻导航：全部便签、含图片、最近删除；用导航替代顶部堆叠的筛选下拉框。
- 顶部只留“我的便签 / 数量”、搜索、新建和轻量同步状态。没有真实内容时使用引导，不制造假便签或统计数字。
- 主区 3–4 列卡片，宽约 240–300 px、竖向比例统一。每张显示标题、数行正文、真实图片缩略预览和更新时间；主题色浅染卡片，与桌面一致。长内容截断预览，完整内容在阅读区呈现。
- 点击卡片，右侧打开约 560 px 阅读面板，保留网格位置。展示完整文字、图片及复制、历史版本、编辑、删除；可展开阅读。手机使用全屏阅读并保留返回入口。
- 桌面富文本便签继续在网页只读，说明在桌面端编辑，避免保存时破坏原格式。图片可查看原图、复制/下载；私有附件懒加载并释放临时 URL。
- 搜索、最近删除恢复、断网/同步失败、登录过期草稿保留都需要完整状态；此展示调整不新增无依据的“分享”或“协作”按钮。

官网已实现主题色卡片与侧边阅读，完成真实浏览器桌面与 390px 手机宽度验收；修复双滚动条并调整手机字号。桌面 RTF 保持只读，私有图片懒加载并释放临时 URL。后端迁移为 002_sessions、003_auth_events，独立迁移完成后才升级正式 API，启动服务不执行 DDL。旧桌面有效 Bearer 只在首次迁移后 14 天内可升级，迁移不会反复延长窗口。详细结果见 session-release-2026-10-23.md。
