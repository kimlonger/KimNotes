# 桌面账号与便签同步 · 2026-10-23

客户端入口在托盘「账号与云同步」及设置标题栏。邮箱、密码在 EXE 内输入，使用与官网相同的账号；不加载验证码或内嵌浏览器。注册按钮通过 UseShellExecute 打开系统默认浏览器，目标为 https://note.kimlulu.com/login/?mode=register 。密码不落盘，30 天会话令牌用 Windows 当前用户 DPAPI 加密。

客户端 API 固定为 HTTPS 域名 https://note.kimlulu.com/api/v1/apps/kimnotes ，不会固定解析 IP，不含网关或数据库密钥。桌面密码登录为 /auth/desktop/login，沿用后端密码校验及每 IP / 每账号频率限制，返回 app-scoped desktop Bearer；网页登录注册仍由 Turnstile 保护。

本机 RTF 和配色先正常落盘。登录后自动同步，变更保存后约 3 秒触发，平时每 30 秒检查云端。上传前持久化操作编号和内容，重试保持幂等；push 的 cursor 不覆盖 pull 的 cursor。检测到网络期间新编辑时暂停云端覆盖，后续由服务器保留冲突副本。所有权索引及同步队列按账号隔离，退出不删除本地副本，但其他账号不显示或上传原账号便签。无痕模式不登录、不上传。

富文本通过限额 gzip/base64 字段 rtfGzip 保留原始格式与嵌入图片，同时提取私有图片附件供官网显示；压缩字段最多 2 MB，解压最多 32 MB；拒绝嵌入对象和外部文件表。网页可显示桌面内容，富文本便签在网页中只读，防止丢失格式。网页新建的文字和图片可下载回桌面。布局、待办及截图历史不进入此次同步。

## 登录中跨屏裁切与图片操作修订

复现了用户反馈的特定时序：服务端已完成账号验证，CloudSync.SignIn 仍等待首次同步，账号窗口在 working 期间忽略 Changed；跨屏排版读取已成立的 Session 并缩小窗口，登录输入区尚未切换，产生 400×279 窗口内仍显示完整登录表单的裁切。先用可暂停的模拟认证/同步请求加入失败回归，再修复为统一的视图状态与成组控件切换，并在首次同步未完成时及时显示“已登录”和“正在同步”。这项修订改善反馈，不声称缩短了真实服务器处理耗时。

便签图片原先使用 GetCharIndexFromPosition 做命中，点击图片中部会返回图片后面的字符；菜单因此漏判。现在通过 RichEdit 的图像对象位置和实际尺寸判断命中，复制为可供其他软件粘贴的 Bitmap，Ctrl+C 在原生富文本复制前处理。选中图片展示八个手柄：角点等比缩放，边缘自由修改单一尺寸；保留原始像素、周围文字、撤销和保存后重开结果，Esc 可取消预览。按用户最终要求，图片右键只留“复制图片、查看大图、删除图片”，不展示文字编辑、另存为或调整大小菜单。
