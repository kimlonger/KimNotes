# v1.4.13 桌面与图片同步修复

本轮包含图片缩放残影、列表响应速度及逐条同步状态、图片同步超限、新便签位置、固定工具栏、删除线与选区翻译。原有工作区修改保留，本轮没有提交或推送 Git。

## 桌面交互

- 快速连续拖动会使 Win32 子窗口边框留下旧像素。合成鼠标消息突发复现了 10,354 个残留像素；对旧、新边框区域立即重绘后为 0。拖动预览不修改正文，松开才产生实际编辑，Esc 取消。
- 图片尺寸变更显式标记 RichTextBox 已修改；原文不变的图片缩放与撤销同样能够保存。子编辑器完成 DPI 变化后重新排列控制柄。
- 新便签以当前或最近的便签为锚点错位打开，边缘换位；已有便签继续使用保存位置。恢复尺寸使用与保存值一致的 WinForms DPI 坐标，避免原生查询与托管 DPI 短暂不同导致缩小。
- 工具栏采用固定尺寸及间距，紧凑左对齐。大小写转换删除，替换为原生字符格式删除线，只改对应样式位，保留混合字体与颜色。
- 翻译仅读取选区，自动判断英译汉或汉译英，跳过数字、日期、科学计数及符号。请求在后台进行，防止重复点击；选区变化、关闭窗口或请求失败时不误插入结果。

## 列表与同步

列表实现与验证见 [列表性能记录](history-performance-20261023.md)。索引和 RTF 解析在后台 STA 完成，解析前去除图片，按需创建原生卡片，保存成功后只更新内存索引。

登录后显示已同步、待同步、同步中、同步失败或需重新登录。同步状态更新不重建列表。内容散列缓存以文件长度、修改时间和主题为依据，实际散列在后台计算，保存时主动失效。

每条便签单独处理可恢复的数据/大小错误，失败原因持久化；未改变的失败便签不每 30 秒重复编码。编辑后自动重试，“立即同步”会显式重试失败项。网络或登录错误仍保持原有全局退避、凭证续期和重放规则。

远端变更若暂时无法合并，先持久化到 `Deferred` 再推进拉取游标，其他便签继续接收。下一轮先上传本地修改，再处理待合并变更；冲突保留两个版本。新修改发生在上传期间时不会把旧快照标记为已同步。

云端导入还原及 RichEdit 标准化在后台 STA 执行，最终写入前再次保存、检查本地修改，避免临时 UI RichEdit 影响消息循环和覆盖用户输入。
